# Quality check 2026-11-01

The ten engineering rules, checked against the code at this commit.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Every call can fail | fixed | Every network call has a deadline: UDP receive loop on a `System.nanoTime` deadline (`UdpTransport.java:58-70`), TCP connect and read timeouts (`UdpTransport.java` `tcp`), per-query timeout and a query budget in the resolver, idle timeout and 408 in `HttpServer`, `create_connection(timeout=5)` and `sock.setTimeout(5000)` in the Python and Node clients. Swallowed errors found: `HttpServer` answered handler exceptions with 500 and skipped selector I/O errors without a trace; both are now counted (`errors()`) and logged (`HttpServer.java:165,227`). The `DnsServer` used by tests and the benchmark still drops malformed datagrams and I/O errors on purpose (it imitates a server that ignores garbage); this is documented in its Javadoc. |
| 2 | Writes safe to retry | N/A | No persistent writes. `ResolveCli --capture` writes one hex file per reply, named by reply index, overwritten on a rerun. DNS queries and HTTP GETs are idempotent; POST bodies are only echoed by the demo handler. |
| 3 | No race conditions | fixed | `HttpServer.conns` was an `ArrayList` mutated by the selector thread and read by `openConnections()` and `close()` on other threads; now `ConcurrentHashMap.newKeySet()` (`HttpServer.java:83`). Counters are `AtomicLong`; `DnsCache` methods are `synchronized`. CI runs the Java tests on Linux; no Go code. |
| 4 | Don't trust the clock | fixed | DNS cache TTLs were aged on `System::currentTimeMillis` in `ResolveCli` and `Bench`, so a wall-clock step would expire or revive records. Now `DnsCache.MONOTONIC_MILLIS` (`System.nanoTime`, `DnsCache.java:42`). All latency measurements already used `System.nanoTime`. No stored timestamps. |
| 5 | Read before changing | pass | No environment variables are read by the Java code; the Python/Node harnesses read none beyond passing the environment to the child JVM. All README paths exist (`audit_repo.py` OK). |
| 6 | Never break compatibility | pass | Wire formats follow RFC 1035/9112 and are pinned by captured fixtures. New public API is additive (`errors()`, `MONOTONIC_MILLIS`). |
| 7 | One source of truth | pass | The cache states its source (the answering server) and invalidation (TTL, capped at one day; negative entries at the SOA minimum; LRU bound). Java 21, Node 24, Python 3.12 agree across README, `pom.xml`, `package.json`, workflow. |
| 8 | No secrets, validate input | fixed | Secret grep finds nothing. The HTTP parser bounds request line, header bytes, header count and body. `ResolveCli --timeout-ms abc` threw a stack trace and `0`/negative values were accepted; now exit 64 with a message (`ResolveCli.java:36-58`). |
| 9 | Tests that can fail | fixed | No skipped or assertion-free tests. 8 of 18 Java hand mutants survived; 7 killed by new tests, 1 is equivalent (table). |
| 10 | Re-verify | pass | `bash .tmp/check.sh`: `Tests run: 109, Failures: 0`, Python `20 passed`, Node `pass 9`, all three audits clean, `network-stack-from-scratch: OK`. CI result in the commit history. |
